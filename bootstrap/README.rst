=========================
Injector bootstrap script
=========================

``sitecustomize.py`` is the bootstrap script that triggers loading of the Dash0
OpenTelemetry Python distribution. A consumer (for example the Dash0 operator's
instrumentation image) places a directory containing this file on the target
interpreter's ``PYTHONPATH`` via the `OpenTelemetry injector
<https://opentelemetry.io/docs/zero-code/python>`_, and CPython then runs it
automatically on startup. The script:

- verifies the interpreter is a supported CPython (3.10+) and bails out
  gracefully otherwise;
- guards against double instrumentation when the target application already
  ships OpenTelemetry packages;
- self-deactivates for child processes to avoid conflicting ``opentelemetry-*``
  versions;
- bridges ``OTEL_EXPORTER_OTLP_ENDPOINT`` to ``DASH0_OTEL_COLLECTOR_BASE_URL``;
- imports and initializes the OpenTelemetry auto-instrumentation.

At runtime it reads an ``all-dependencies.txt`` file from its own directory for
the double-instrumentation conflict check. That file is generated by the
consumer when it assembles the injected package tree; it is not part of this
repository.

Why this lives outside the distribution package
================================================

This file is intentionally **not** part of the ``dash0-opentelemetry-distro``
package and is never imported by it. It must stay valid **Python 2.7+** so that
it can detect a legacy interpreter and bail out cleanly instead of crashing with
a ``SyntaxError``. For that reason ``bootstrap`` is excluded from the repository
ruff configuration (the ``UP``/pyupgrade rules would rewrite its
2.7-compatible constructs into 3.x-only syntax).

Consumers should copy ``sitecustomize.py`` out of this directory rather than
maintaining their own copy.
